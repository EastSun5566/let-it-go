# OffscreenCanvas Worker spike result

## Verdict

The Worker prototype has a **mixed cross-platform result** and does not yet justify a production implementation.

Both macOS and Ubuntu move more than 92% of measured task time off the main thread at 5,000 and 10,000 flakes. The valid macOS run fails the gate because default-count memory increases by 18.30%, while the valid GitHub Actions Ubuntu run passes with a 3.94% memory increase. macOS also doubles the 10,000-flake p95 frame interval, while Ubuntu does not.

The environment-sensitive result supports keeping the Worker renderer out of the public API until repeated fixed-runner and macOS measurements establish a stable policy. Any action on issue #60 or PR #62 remains separate from this spike.

## Environment

- Source base: `7d5a6ce9c093b154cb811a37c9deeed939d556d5` plus the uncommitted benchmark spike
- OS: macOS 26.6.2 (25G83), arm64
- Node.js: 24.16.0
- Playwright Chromium: 153.0.8010.12
- Viewport: 1280 x 720, device pixel ratio 1
- Five repetitions per renderer and count
- Two-second warm-up and ten-second measurement window

## Valid local macOS result

All main-thread task coefficients of variation are at or below 10.1%, below the 15% validity limit. The deterministic prototype-main CPU proxy stays within 5.7% of production-main at every count, below the 10% equivalence limit.

| Flakes | Main-thread reduction | Total CPU change | Memory change | p95 frame production -> Worker | p95 interaction production -> Worker |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1,000 | 78.13% | +21.19% | +11.22% | 16.67 -> 16.67 ms | 31.04 -> 30.41 ms |
| 1,280 | 83.45% | +1.57% | **+18.30%** | 16.67 -> 16.67 ms | 27.04 -> 22.06 ms |
| 5,000 | 92.30% | +12.15% | +10.19% | 16.67 -> 16.67 ms | 28.81 -> 33.03 ms |
| 10,000 | 96.46% | -5.57% | -6.53% | 16.67 -> **33.33 ms** | 26.86 -> **41.85 ms** |

Raw evidence: [`2026-09-28-macos-arm64-chromium-clean.json`](./2026-09-28-macos-arm64-chromium-clean.json).

## Valid GitHub Actions result

[GitHub Actions run 36418234175](https://github.com/EastSun5566/let-it-go/actions/runs/36418234175) completed the same 60 measurements on Linux x64 with Node.js 24.21.0 and Chromium 153.0.8010.12. The maximum coefficient of variation was 9.02%, and prototype-main stayed within 7.37% of production-main.

| ---: | ---: | ---: | ---: | ---: |
| 1,000 | 81.90% | +5.31% | +19.18% | 16.67 -> 16.67 ms |

This run passes the agreed gate. Its raw JSON is retained as a 30-day workflow artifact; it is independent evidence rather than a replacement for the macOS result.

## Invalid first run

The first run is retained for auditability but is not decision evidence. A native Safari tab was still rendering 5,000 flakes throughout the run, and four scenario coefficients of variation exceeded 15%. After navigating that tab to `about:blank`, the unchanged benchmark produced the valid result above.

Raw evidence: [`2026-09-28-macos-arm64-chromium.json`](./2026-09-28-macos-arm64-chromium.json).

## Browser coverage

- Playwright Chromium, Firefox, and WebKit: 21/21 functional checks passed.
- Native Safari 26.6.2 selected the real `prototype-worker` path at 5,000 flakes. A ten-second sample completed 599 frames with three dropped frames, a 17 ms p95 frame interval, and a 23.6 ms interaction-latency proxy.
- Safari memory remains `null` because the Chromium CDP heap measurement has no equivalent signal there; Safari is functional evidence, not the performance gate.
